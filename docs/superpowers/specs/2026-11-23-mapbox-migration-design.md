# Mapbox Native SDK Migration — Design Spec

**Date:** 2026-11-23  
**Scope:** Project-level map layer replacement (`flutter_map` + Esri → `mapbox_maps_flutter`)

---

## 1. Intent & Why

Esri raster tiles look dated and lack smooth vector rendering. Migrating to the official native Mapbox Maps SDK (`mapbox_maps_flutter`) gives `rain-reporter` smooth 60fps vector maps, Mapbox Standard 3D-ready styling, and native pulsing user-location rendering on Android while preserving all existing rain-reporting, clustering, and GPS-restriction behavior.

---

## 2. Goals, Non-Goals, and Anti-Goals

- **Goals:**
  - Replace `flutter_map` + `latlong2` + Esri tiles with `mapbox_maps_flutter` using `MapboxStyles.STANDARD`.
  - Render meter-accurate translucent rain zone circles around each `RainCluster` using a GeoJSON source + `FillLayer` + `LineLayer` (64-vertex geographic circle polygons) so zones scale accurately with zoom.
  - Render single-pin markers and circular cluster count badges via `PointAnnotationManager` with tap listeners opening `PinDetailBottomSheet` and `ClusterDetailBottomSheet`.
  - Enable Mapbox's native pulsing blue user-location dot (`LocationComponentSettings`).
  - Preserve all existing UX behavior: Bandung overview (`zoom: 12`) → smooth `easeTo` / `flyTo` animation to user GPS (`zoom: 16`), **My Location** recenter FAB, `400ms` / `500m` debounced pan refresh, GPS-locked **Report Rain**, and `500m` GPS range restriction on **Stopped here** votes.
  - Keep `pk.*` public token out of git in gitignored `mapbox.json` (`--dart-define-from-file=mapbox.json`) and `sk.*` download token in `~/.gradle/gradle.properties`.
- **Non-Goals:**
  - Web (Chrome) or Linux desktop Mapbox support (`mapbox_maps_flutter` only supports Android & iOS).
  - iOS setup/provisioning (Android remains the sole build target).
  - Custom Mapbox Studio style authoring (use built-in `MapboxStyles.STANDARD`).
- **Anti-Goals:**
  - Never commit `pk.*` or `sk.*` Mapbox tokens to git.
  - Never regress `flutter test` speed or break widget tests by requiring a live native Mapbox GL view in headless unit tests.

---

## 3. Constraints

- **Android Gradle:** Requires `SDK_REGISTRY_TOKEN` / `MAPBOX_DOWNLOADS_TOKEN` (`sk.*` with `Downloads:Read`) in `~/.gradle/gradle.properties` (never in repo).
- **Runtime Token:** Read `const String.fromEnvironment('MAPBOX_ACCESS_TOKEN')` and call `MapboxOptions.setAccessToken(...)` in `main()` before `runApp()`.
- **Testability:** Extract a clean `RainMapView` / controller abstraction (or keep `useNativeMapView = false` test mode) so `flutter test` exercises `MapScreen` camera moves, pan debounce, reporting, clustering, and voting without native platform views.

---

## 4. Approaches Considered

1. **Native `mapbox_maps_flutter` SDK (Picked):** Full native Mapbox GL vector rendering with `MapboxStyles.STANDARD`, GeoJSON polygon `FillLayer`/`LineLayer` for meter-accurate rain zones, `PointAnnotationManager` for pins/clusters, and native `LocationComponentSettings`.
   - *Tradeoff:* Drops Chrome web support and requires `sk.*` Gradle token + rewriting `MapScreen` map wiring, in exchange for flagship 60fps vector map UX.
2. **Mapbox Raster Tiles inside `flutter_map`:** Keep `flutter_map` and swap tile URL to Mapbox Styles API.
   - *Tradeoff:* Simpler migration and keeps Chrome web support, but stays raster-only without native Mapbox Standard vector rendering.

---

## 5. Architecture & Decided Behavior

- **GeoJSON Rain Zone Helper (`lib/domain/rain_zone_geojson.dart`):**
  - Pure Dart helper converting `List<RainCluster>` into a GeoJSON `FeatureCollection` of 64-vertex circle polygons (using haversine destination formula in `LocationPrivacy` / `dart:math`) with properties (`colorHex`, `borderColorHex`, `clusterIndex`).
  - Unit-testable without Flutter/Mapbox native bindings.
- **Marker Bitmap Renderer (`lib/ui/mapbox_marker_icons.dart`):**
  - Renders crisp `Uint8List` PNG bytes via `dart:ui` `PictureRecorder`/`Canvas` for:
    - Single rain pins (colored teardrop/pin by `RainIntensity`).
    - Cluster badges (44×44 colored circle with white border and bold report count).
  - Caches generated bytes in memory by `(intensity, count)` so pan/stream updates don't re-rasterize unnecessarily.
- **Map Widget (`lib/ui/map_screen.dart`):**
  - When `useNativeMapView == true` (production Android): renders `mapbox_maps_flutter`'s `MapWidget` (`styleUri: MapboxStyles.STANDARD`), wires `onMapCreated`, `onCameraChangeListener`, GeoJSON `FillLayer` + `LineLayer`, `PointAnnotationManager` + tap listener, and native `LocationComponentSettings(enabled: true, pulsingEnabled: true)`.
  - When `useNativeMapView == false` (headless `flutter test`): renders a lightweight test surface driven by an injectable test controller so all camera, pan-debounce, cluster-tap, and vote flows remain fully covered in `flutter test`.
- **Token & Build Config:**
  - Add `mapbox.json` to `.gitignore` with `{"MAPBOX_ACCESS_TOKEN": "<pk.*>"}`.
  - Add `mapbox.example.json` (placeholder) to repo for documentation.
  - Pass `--dart-define-from-file=mapbox.json` for `flutter run` and `flutter build apk --release`.

---

## 6. Left to the Builder (Defaults)

- Exact `mapbox_maps_flutter` version resolved from pub.dev (`^2.x` compatible with Dart 3.13 / Android Gradle 9.1).
- Exact polygon vertex count (`64` vertices per circle) and fill/line opacity (`0.28` fill, `0.75` border, `2.0` line width) matching current visual design.
- Pin/badge bitmap scale (`2.0x`–`3.0x` pixel ratio for sharp rendering on high-DPI Android screens).
